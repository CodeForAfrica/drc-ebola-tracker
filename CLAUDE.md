Context for Claude Code working in this repository.

## What this project is

A single-page, map-based dashboard of the 2026 Bundibugyo ebolavirus (BVD) outbreak in DRC, with the other countries reporting confirmed cases (Uganda, Kenya, Nigeria). It is **plain HTML/CSS/JS**, split into a reusable engine (`index.html` shell, `styles.css`, `app.js`) and one outbreak config (`config.drc-bvd-2026.js`) — see [TEMPLATE.md](TEMPLATE.md). Leaflet is vendored in `vendor/leaflet/`; there is no Chart.js.

- There is **NO framework** and **NO build step**. The site runs by opening `index.html` directly in a browser.
- **Do NOT** convert it to React (or any framework), and **do NOT** add a bundler, package manager, or build tooling. Keep it as vanilla HTML/CSS/JS loaded with plain `<script src>` tags (no `fetch()` of local files, so `file://` keeps working).

> **The two rules above govern the vanilla tracker (`index.html`/`styles.css`/`app.js`/`config.drc-bvd-2026.js`), which stays no-build and `file://`-openable. They are NOT relaxed.** A separate React front end lives under `site/` — see the next section.

## Site (React) — `site/` (Option B; added by PR, pending maintainer sign-off)

A second, richer front end built with **React + TypeScript + Vite + Tailwind + Leaflet + Recharts** in Code for Africa's visual identity. It is deployed by `.github/workflows/pages.yml`, which also copies the **unchanged** vanilla tracker to **`/explore/`** in the published output. The vanilla tracker and its files are not modified.

**`site/` holds NO figures — it is a read-only view of this repo's data.** Every value comes from `site/src/data/*.json`, produced by `npm run data` (in `site/`), which runs:
- `scripts/extract.cjs` → copies `D.nat2`, `PROV`, `CTRY`, `D.zones/geo/trends/mob`, `BASE` geometry (precision-reduced only) and selected `T.en` strings from `../config.drc-bvd-2026.js` into `src/data/tracker.json` — **one for one, no value edited** — and builds `ctryHist` (per-country reported history for the Trends view): Kenya and Nigeria read one point per statement from `../data/kenya_moh.csv` / `../data/nigeria_fmoh.csv`, Uganda's single final figure from its `CTRY` row. Nothing is typed or interpolated;
- `scripts/first_listed.cjs` → derives each zone's first-listed date from `../data/zones_timeseries_full.csv` + the zone series into `src/data/firstListed.json`.

`src/data/admin1.json` is **geoBoundaries gbOpen ADM1 geometry only** (Kenya counties, Nigeria states; CC BY 4.0) — not derived from the config. The CI workflow runs `npm run data` on every build, so a SitRep update to the config reaches the site with no extra edit.

**Standing rules for `site/`** (keep in sync with the live tracker's ethos):
- If a figure needs typing into `site/src`, it is in the wrong place — it belongs in the config/`data/` and the scripts.
- Derived values (daily change, shares, rankings, first-listed dates) live in `src/lib/data.ts` / `src/lib/briefing.ts`, each with a comment on how it is derived.
- A **daily change** is shown only between **consecutive daily reports**; **nothing is interpolated**. The national **Trends** chart marks missing reports with a dashed bridge; the **per-zone** cumulative chart (cases in blue, deaths in red) connects its real readings across gaps as a continuous line (no synthetic points; tooltips show only reported readings). **Trends covers every affected country** via a country switcher: DR Congo keeps its full daily SitRep charts; each other country shows its ministry statements as discrete reported points (Kenya/Nigeria from `ctryHist`, Uganda's single final point) plus a statements table — never a daily line, since those ministries publish periodically. Country bubbles are **small proportional symbols** (√-scaled SVG circleMarkers in the map's own renderer, centred on each country's outline, active ones carrying a slow pulse ring); drawn in the SVG renderer they track the map on zoom without floating. The Briefing's **cross-border chapter** (chapter 3) puts those same country bubbles on the story map, framed across the region, so the countries are on screen while the cards tell the chronology — each card lights up its own country (`MapSpec.mode: 'countries'`).
- **EN / FR toggle** (TopNav). Language lives in `src/lib/i18n.tsx` (`L(en, fr)` resolves at call time; `LangProvider` + a per-language remount of the map/briefing re-render the tree). Dates and numbers follow the locale (`fr-FR` groups with a space). French copy is **AI-assisted and flagged for Francophone review** (as on the live tracker, TODO_KIKI); the Methods coverage/mobility passages reuse the config's own French (`T.fr`, carried to `tracker.json` as `stringsFr` by `extract.cjs`). No figure is translated — only labels and prose.
- **Facility finder** (`Facilities` page, `src/sections/Facilities.tsx`). A chat-style finder returns the nearest hospitals/clinics/pharmacies to the visitor (browser geolocation, kept client-side) or to a typed health zone / country, computed with a Haversine distance over `src/data/facilities.json`. That JSON is reduced by `scripts/facilities.cjs` from the committed mirror `data/health_facilities.csv`, itself regenerated by `tools/fetch_facilities.js` from the **HOT OpenStreetMap "Health Facilities of {country}"** exports on HDX (**ODbL, © OpenStreetMap contributors**; current as of 2 Nov 2026; 21,366 named + located facilities across the four countries). It is community data, labelled as such, never an official registry — and the **one place the site goes below health-zone granularity**. This is a **new data source + a sub-health-zone view: both require maintainer (Eric) sign-off** before merge, like the HANDOFF §3 amendments. No value is invented; a facility with no name or geometry is dropped. A static site has no backend, so the finder is deterministic (not an LLM).
- **"No data" is never drawn as zero.** Kenya / Nigeria subdivisions are **never coloured** by a value (national figures only).
- Mobility is always labelled **Flowminder / Vodacom April 2026 estimates** — importation risk, not transmission; suppressed flows are never counted as zero.
- **Early-warning** levels are now computed from the per-zone cumulative series as **automated signals with provisional thresholds** (maintainer decision, amends the earlier "stay empty until the epidemiology team supplies thresholds" rule). The page classifies each reported zone Critical / Alert / Normal / Not-assessed from `site/src/data/ews.json`, produced by `site/scripts/ews.cjs` (wired into `npm run data`) from `../data/zones_timeseries_full.csv` — same rules as `tools/ebola_early_warning.py` / `early_warning/RULES.md`. Three indicators are active (new zone within 21 days; 7-day rolling new cases ≥ 25 alert / ≥ 50 critical; new case after ≥ 42 quiet days, within 21 days); the rest (week-on-week growth, contacts, community-death share, mobility) stay pending (the per-zone series can't support them). **No figure is typed into `site/src`** — every value is derived in the script. The page is labelled "automated signals, provisional thresholds, to be confirmed by the epidemiology team" and keeps the "verify against WHO" note. The **map `ews` layer** also colours each zone by level (`--ew-critical/alert/normal`; `na` hatched), with a matching tooltip, legend and Overview-sidebar summary — all reading `EWS_LEVEL`/`EWS`/`EWS_ZONE` from `src/lib/data.ts` (which imports `ews.json`).
- The **"Verify against WHO before publishing"** note stays visible on every page.

**Amends standing rules — requires maintainer (Eric) approval before merge** (HANDOFF §3): (1) `site/` uses a framework + CI build step (the vanilla tracker under `/explore/` stays no-build and `file://`-openable); (2) `site/` uses the Code for Africa identity instead of the dark situation-room theme; (3) `site/` uses the **keyless Esri Gray Canvas basemap** (`services.arcgisonline.com/.../Canvas/World_{Light,Dark}_Gray_Base`, OpenStreetMap data), attributed on the map and in Data & methods — switched from CARTO, whose keyless basemaps now stamp an "API KEY REQUIRED" watermark; (4) new data source **geoBoundaries gbOpen ADM1** (CC BY 4.0, geometry only) for Kenya/Nigeria outlines, credited on the map and in Data & methods. Until the new site reaches feature parity, the vanilla tracker is kept under `/explore/` (parity gaps: time filter, CFR & Risk-level indicators, ND contact-tracing/suspect markers, full Methods text, zone search by province).

## Current design — "Epidemic Intelligence" (redesigned)

The dashboard was rebuilt to a new layout ("Epidemic Intelligence · Bundibugyo 2026"): a full-bleed map with a floating map-indicator selector, search box, log-scaled legend and a Latest-only time bar, plus a right sidebar with a national + provincial overview and a per-zone view (snapshot, trends chart, mobility panel). Leaflet is vendored (`vendor/leaflet/`); charts are hand-drawn SVG (no Chart.js). Key points for future edits:

- **Data model:** all data is a single `const D` object in `config.drc-bvd-2026.js` — `D.zones` (the 68 mapped health zones of the 69 reported `{z,p,c,d,lat,lon,pop,cfr,k}`), `D.geo` (INRB-UMIE archived v1 shapefile polygons for those 68 zones, `properties.z`), `D.cent`, `D.trends` (per-zone daily series, extended with break rows to the 04 Aug and 05 Sept readings, then daily readings 07 Sept–02 Oct from N°116–141, a break row for the unpublished N°142, daily 04–10 Oct from N°143–149, a break row for the held N°150, daily 12–29 Oct from N°151–168, a break row for the held N°169, daily 31 Oct–1 Nov from N°170–171, a break row for N°172 (not published as of 5 Nov), and daily 3–24 Nov from N°173–194), `D.nat2` (national time series whose **last row is the live N°194 headline**; a row may carry `nd:{ct:[…],sus:[…]}`, the provinces that SitRep records as not reported (ND) for contact tracing / suspects, plus `ctn` when `ct` comes from the report's own named list of transmitting provinces, so the note reads "covers the {n} provinces INSP lists as transmitting; … are not among them"), `D.tl`, and `D.mob`. National render uses `live=false`, reading the N°194 row from `D.nat2` (12021 cases / 5904 deaths / CFR 49.1% / 3332 recovered / 1092 isolation / 85.1% contact tracing / 446 suspects; contact tracing marked * for Sud-Ubangi, ND in Tableau 4). The previous design's `HZ`/`POP` arrays, `fetch()` of the geojson, `applyStaticI18n`, collapsible panels, etc. are gone.
- **Map base:** OpenStreetMap tiles only (Leaflet), desaturated via the `--tile-filter` CSS. The design's vector base and the Vector/OSM switcher were removed at the maintainer's request; `basePane` is hidden and country labels are a no-op.
- **Mobility is populated from Flowminder / Vodacom, April 2026** (integration test). `D.mob` is built by the adapter `tools/build_mobility.js` from the committed mirror `data/mobility_flowminder_od.csv`, which is itself extracted from the INRB-UMIE open-data release (`INRB-UMIE/BDBV2026-Data`, `data/flowminder/raw/drc-estimated-relocations-2020_03-2026_04-v2.0-external.csv`, column `est_flows_2026_04` + `_LB`/`_UB`) by `tools/extract_flowminder_od.js`. Schema: `D.mob[zone]={tin,tout,in:[[orig,est,lo,hi]…],out:[[dest,est,lo,hi]…],inSup,outSup}`, directed (A→B stays A→B; `in`=destination is this zone, `out`=origin is this zone), covering only the original 51 mapped health zones (**Mangala** and **Vuhovi** have no Flowminder coverage, and the 13 zones mapped on 8 Oct 2026, Wapinda (19 Oct), Yakoma (30 Oct), Watsa (16 Nov) and Kibirizi (25 Nov) have no rows in the mirror CSV; all 19 render the "no coverage" state; the 5 spelling aliases are in the extractor). **Rules:** never invent mobility values; flows Flowminder marks `redacted (count <15)` are `status=suppressed` and are **never counted as 0** (tracked as `inSup`/`outSup`); keep the published lower/upper bounds; keep the Flowminder / Vodacom provenance and the "Vodacom subscribers only; Flowminder-derived estimates" wording visible (this is an integration test — do **not** claim a separate redistribution licence). To add a future month, append rows to the mirror CSV with a new `month` value and re-run the adapter — do not rewrite the mobility UI.
- **i18n (EN / FR):** the 🌐 button toggles English ⇄ French. Strings live in a `T={en,fr}` dictionary; static markup carries `data-i18n` / `data-i18n-html` / `data-i18n-ph` / `data-i18n-aria` / `data-i18n-label` and is filled by `applyStaticI18n()`, while the dynamic renderers call `tx(key)`. `setLang()` swaps `LANG`, re-applies static i18n and re-runs the renderers; the choice persists in `localStorage.lang`. **The translate function is `tx`, not `t`** — the render functions already use `t` as a local for the current timeline row, so `t` must not be shadowed. French copy is AI-assisted and needs Francophone review (TODO_KIKI).
- **Methods modal** (`#mmodal`, the "Data & Methods" button) carries the sources, the coverage disclosures (493 "A ventiler" Ituri deaths, excluded from zone-level totals: reported zones sum 12021 / 5411 vs national 12021 / 5904; Dakwa unmapped; the ND rule; the held N°150 in `mm_cov_held` and the held N°169 in `mm_cov_held169`) and, in Sources, the geometry provenance (INRB-UMIE archived v1 shapefile) and the CSV downloads. ## Data handling

- The figures are **embedded in `config.drc-bvd-2026.js`** (`D`, `NAT`, `PROV`, `CFG`, `T`) and are **also mirrored in `data/`** as CSVs. A few release labels also sit in the `index.html` shell markup (header meta, stamps, download links).
- If any figures change, **keep all copies in sync** — the config, the `index.html` shell text, and the corresponding file(s) in `data/`. `app.js` holds no figures; if an update needs an `app.js` edit, a value has leaked into the engine.
- **SitRep parity (standing rule).** Every national and province figure the dashboard shows must equal the SitRep exactly as printed: national = page-1 banner, province = the province table (Tableau 1: cases, deaths, printed CFR, zones affected). Province totals live in `PROV` in the config (mirrored in `data/provinces_sitrep<NNN>.csv`) and the engine reads them; it only falls back to summing zones when a config has no `PROV`. **Before applying any update, list every dashboard-vs-SitRep discrepancy and the proposed fix, then fix it.** Never make totals agree by redistributing, estimating or dropping figures: unassigned ("A ventiler") deaths stay out of every zone and are counted only in their province and national totals, and unmapped zones stay off the map but inside their province totals.
- **Never invent or estimate numbers.** Use only figures explicitly published by **each country's own public-health authority**: INSP for DRC, the national ministries of health for Uganda, Kenya and Nigeria. **WHO** (Disease Outbreak News) and **Africa CDC** are cross-checks, not sources for a displayed figure. (Amended 22 Oct 2026 when Kenya and Nigeria were added; it previously named WHO and Africa CDC as the only sources.) Aggregators and news reports (e.g. ebola-tracker.org, AP) are cross-checks only and are never cited. If a number isn't in a cited source, leave it out rather than guessing.
- Keep all outputs **aggregated to health-zone level** (or coarser: province/country). Do not produce or display anything more granular than health zone.
- Keep the **"verify against WHO before publishing"** note visible in the UI. Do not remove it.
- **Two GeoJSON files in `data/` look interchangeable but are not.** `zones_sitrep0XX.geojson` carries per-zone `confirmed_cases`/`confirmed_deaths` and is what the live choropleth `fetch()`es. `zones_geometry.geojson` carries **geometry only** (46 zones, no counts) and is staged for a future CSV-driven refactor — it is **not wired up**. Do not point `fetch()` at `zones_geometry.geojson` without also changing how the choropleth reads counts, or the map will render unfilled with no error.
